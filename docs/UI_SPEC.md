# UI_SPEC.md — 共享空间 V1 界面规范

> 版本 V1.0 · 开发基线 · 依据《V1 精简技术实施规范》四

## 1. 设计关键词

`简约 · 安静 · 留白 · 日记感 · 白色 · 克制`

**不是**：社交媒体、游戏化、高饱和、复杂玻璃拟态。

## 2. 导航

- 手机：**抽屉式侧边栏**。
- 主要入口：共享日记 / 我的记录 / 当前空间 / 空间设置。
- 未来功能（书影音、全国地图）V1 不显示，**不要**显示「即将推出」占位入口。

## 3. Splash

- 背景：白。
- 中央文案：「我想去盛满你所有野蛮的星球，庆祝文明不再扼住我们的喉咙。」
- 底部小字：「共享空间」。
- 停留约 2 秒。
- **Splash 不是业务页面**：不发网络请求、不等待后端。可后台初始化本地配置 / 登录状态 / 基础客户端服务；初始化超时不得永久阻塞应用。

## 4. 登录页

- 居中卡片式布局，大面积留白，白色/近白色背景，不设头像、不用复杂背景图。
- 字段：邮箱、密码、登录；注册作为次级操作。
- V1 不加：第三方登录、手机验证码、社交登录（除非后续需求明确提出）。

## 5. 共享日记首页

```
共享日记             ＋
[月] [周]
内容区
```

新建按钮一直可访问。

## 6. 月视图

- 标准月历；有日记的日期显示**明显但克制**的标记。
- 点击某一天 → 当日日记集合。
- 月历格子内**不要**塞：头像、日记摘要、心情列表、天气文字。

## 7. 当日日记

- 一个日期下可以是 1 人记录，也可以是多人记录。
- 按 `created_at ASC` 展示，每篇独立（时间 + 作者昵称 + 正文）。
- 每个人的记录均公开。

## 8. 周视图

- 目标：七天中不同时间段有多少成员留下记录。**不是**每个人的独立时间轴。
- 布局：7 列（周一到周日）× 小时行（08:00–23:00）。
- 单元格颜色深度 = 该时间段**不同成员数**：0 人 → 空；1 人 → 很浅；2 人 → 中等；3 人及以上 → 更明显。
- 色阶必须来自统一 **Design Tokens**，不得各页面自行指定颜色。

## 9. 周视图点击

点击一个时间格（如周三 14:00–15:00）→ 查看该时间段所有成员创建的日记。不让用户在网格中区分每个人。

## 10. 新建日记

```
←
日期        （系统自动使用当天，仅展示；V1 不提供修改 UI）
天气  心情
正文
图片        （最多 9 张）
保存
```

不要求补充「记录时间」。空正文不允许保存（客户端校验）。

## 11. 编辑日记

允许改：正文、天气、心情、增删已支持的图片。
**不修改创建时间；V1 不提供修改 diary_date 的 UI**（Milestone 2 产品决定）。
可显示：创建时间、（可选）最后修改时间。

## 12. 删除日记

- 删除按钮只出现在**作者自己的日记**中。
- 确认文案：「删除这篇日记？」
- 确认后直接删除（V1 无回收站）。

## 13. 图片

选择图片 → 压缩 → 上传。单篇最多 9 张；上限集中定义（见 API_SERVICE.md §16）。

## 14. 日记详情

显示：作者昵称、创建时间、天气、心情、正文、图片、批注。
作者：可以编辑、删除。其他成员：只可以阅读、批注。

## 15. 划线批注

```
长按 / 选中文字 → 批注 → 输入评论 → 提交
```

- 被选中的文字：使用**批注作者**对应的轻量标记颜色（底色或下划线）。
- 点击标记 → 打开批注卡片：`小王 · 18:42` + 评论内容。
- 不显示头像；昵称必须始终显示。用户个人标注颜色可用于批注标识、用户名、相关高亮。

## 16. 我的记录

- 只显示当前用户自己写过的日记，按日期排序。
- 这是**同一 DiaryEntry 的不同视图**；禁止建立第二份个人日记数据。
- 「我的记录」页其他成员无法看到（但其中属于共享空间的那条日记仍可在共享空间被看到）。

## 17. 空状态

| 场景 | 文案 |
|---|---|
| 共享日记无内容 | 今天还没有留下记录。 |
| 我的记录无内容 | 还没有写下第一篇日记。 |
| 空间无内容 | 创建一个共享空间，和朋友开始记录吧。 |

## 18. Loading

尽量页面局部 loading / skeleton；不要每次查询都锁死整个 App。

## 19. Error

统一格式：

```
发生了一点问题
请检查网络后重试
[重试]
```

不得直接显示 `PostgrestException...` 原文。

## 20. 状态管理

页面状态由 Controller/ViewModel 经统一状态管理方案（Riverpod）维护；核心数据必须存在于明确的数据流中。
